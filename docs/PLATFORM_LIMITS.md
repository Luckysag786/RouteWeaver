# 平台能力边界（验收时必须阅读）

## 为什么“支持所有 VPN、所有 EXE、所有 APK”不能由一个普通工具保证

1. Windows 目标 IP 路由表不包含进程维度。按 EXE 改写连接需要 WFP 的 ALE Connect Redirect 内核驱动，驱动必须经过微软签名；普通 Python 程序无权获得这一能力。
2. HTTP/SOCKS 系统代理能覆盖浏览器及大量桌面软件，但不覆盖 UDP、QUIC、游戏自建协议或明确忽略系统代理的软件。
3. Android 只允许一个主要 VPN 传输。新的 `VpnService` 启动会取代现有 VPN，因此独立 APK 无法在第三方 VPN 保持运行的同时再接管并重路由所有应用。
4. 公网出口 IP 只能由远端服务观察。工具使用公开 IP 情报 API 的实际响应并保留来源/时间；不会根据规则“推算”或伪造某个 IP。

## 本项目的真实保证

- 对第三方 VPN 暴露的 Windows HTTP 与 SOCKS5 链路执行真实分流测试。
- 不结束、不重启、不写入第三方 VPN 进程或安装目录。
- 启用时只改变当前用户 Windows 代理入口，且可恢复。
- 对每条已经过网关的 TCP/HTTP(S) 连接记录实际决策；未经过网关的连接不会显示为已接管。
- Android APK 不会抢占当前 VPN，提供诚实的兼容性诊断与规则配置。
- Android APK 会发现已安装 VPN 并尝试显式规则交接；提供商未实现接口时复制规则并打开其应用。
